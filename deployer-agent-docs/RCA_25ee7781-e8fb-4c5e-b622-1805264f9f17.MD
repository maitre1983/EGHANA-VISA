# RCA — Production Hubtel payment mode / unauthenticated callback exposure

**App:** https://eghanavisa.com (deployment `ghana-voa-platform`)
**Mode:** READ-ONLY diagnostic. No data modified, no redeploy.
**DB read:** `ghana-voa-platform-test_database` (production, active run `25ee7781-e8fb-4c5e-b622-1805264f9f17`)

## Requested findings — `settings` document {id:"singleton"}

1. **`hubtel.sandbox` = `true`** ← production is running Hubtel in SANDBOX mode, NOT live.
2. Hubtel credential presence (values NOT printed):
   - `hubtel.api_id` — PRESENT (non-empty)
   - `hubtel.api_key` — PRESENT (non-empty)
   - `hubtel.merchant_account_id` — PRESENT (non-empty)
   - `hubtel.callback_url` — PRESENT (non-empty)
3. **`hubtel.callback_url` host = `eghanavisa.com`** (path points at `/api/webhooks/hubtel`)
4. NowPayments:
   - **`nowpayments.sandbox` = `true`**
   - `nowpayments.api_key` — PRESENT (non-empty)
   - `nowpayments.ipn_secret` — PRESENT (non-empty)
5. `payment_methods` array (`code` / `active`):
   - `hubtel_visa` — active: `true`
   - `usdt_trc20` — active: `true`
   - `usdt_bep20` — active: `true`

## Finding 6 — suspicious paid applications (count only)
Collection `applications`, filter: `payment_status:"paid"` AND `payment_verification.state` missing AND `created_at >= 2026-11-17T15:49Z` (last 7 days):
- **count = 2**

## Conclusion
The stated goal — "confirm production uses LIVE Hubtel mode" — is **NOT met**. Production has `hubtel.sandbox = true` (and `nowpayments.sandbox = true`). With sandbox mode active, Hubtel callback signature/authenticity enforcement is not operating in live mode, which is exactly the condition under which an unauthenticated Hubtel callback could flip an application to paid. The presence of **2** recently-created `paid` applications lacking any `payment_verification.state` is consistent with that exposure (correlation, not proof of exploitation).

## Recommended actions
- Set `settings.hubtel.sandbox = false` (and confirm `nowpayments.sandbox` intent) in the production `settings` singleton so live-mode callback verification is enforced. This is a production DATA change the user owns (admin UI or DB).
- Have E1/main agent ensure the `/api/webhooks/hubtel` handler verifies callback authenticity (signature/merchant match) before marking an application paid, independent of the sandbox flag — a CODE hardening fix.
- Review the 2 flagged `paid` applications manually before any fulfillment.
